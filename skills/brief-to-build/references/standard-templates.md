# Brief to Build 标准三文档模板

## 使用规则

- 只维护本文件定义的三份项目文档。
- 将占位内容替换为项目事实；不适用时写明“不适用：原因”。
- 保留原始材料，不覆盖无关既有文件；同名文件存在时先读取，再更新版本。
- 使用 `REQ-xxx`、`Q-xxx`、`TASK-xxx`、`CHG-xxx` 建立必要映射。
- 使用“明确要求、推断、假设、建议、风险”区分信息性质。
- 表格只用于真正需要逐项比较和映射的内容；长段说明使用短段落或项目符号。

## 5. 总控 Prompt

```text
请使用 $brief-to-build 推进“{项目名称}”。

唯一需求基线：{绝对路径和版本}
执行计划：{绝对路径}
验收与变更记录：{绝对路径}

必须按任务依赖顺序推进。每次只执行一个已获授权的任务：检查前置条件和授权 → 执行任务卡 → 生成输出 → 验证完成标准 → 保存证据 → 更新三份项目文档 → 汇报结果和下一任务。

未获得明确正式启动授权时停在等待状态。任何会改变目标、核心范围、主要交付物、技术路线、成本、数据、外部系统状态或验收标准的事项，先暂停受影响工作并登记 CHG。

保留原始材料和失败结果，不覆盖无关文件，不把推断、宣传或未运行内容写成已确认事实或实测结论。
```
