# Requirements Analysis 严格检查

仅在 `SKILL.md` 定义的严格模式升级条件出现时使用本文件。先完成标准流程，再补充以下治理要求；不要为普通低风险任务默认增加全部台账。

## 目录

1. 材料与来源治理
2. 十二维完整性复核
3. 严格授权复核
4. 完整追溯链
5. 变更与验收复核

## 1. 材料与来源治理

在材料多、来源冲突或需要审计时，为每份材料分配 `SRC-xxx`，记录：

- 名称、绝对路径或链接、提供者、日期和版本。
- 原始材料、二手转述、外部参考或 Codex 派生成果。
- 完整性、可访问性、可信度、偏差和处理状态。
- 同名不同版本、缺失附件、不同数字口径和引用链。

保留原件；清洗、解析或转写结果另存，并映射到来源。需要正式决策编号时使用 `DEC-xxx`；不得把记录者概括伪装成决策者原话。

## 2. 十二维完整性复核

在标准八维检查之外逐项确认：

1. **背景与问题：** 为什么现在做，不做的影响，与上级目标的关系。
2. **相关方：** 提出者、决策者、使用者、数据提供者和验收人是否一致或冲突。
3. **目标与价值：** 成功后的可观察变化、非目标和优先级。
4. **场景与流程：** 输入、处理、输出、反馈、异常和失败场景。
5. **对象与数据：** 数据源、规模、质量、敏感性和边界数据。
6. **范围与口径：** “全部、前 N、重点样本、深入研究”的选择标准。
7. **交付物：** 主成果、子成果、摘要、代码、数据和证据如何分工。
8. **深度与证据：** 概览、可行性、设计、源码分析或可运行 PoC；最低证据等级。
9. **资源与依赖：** 人员、账号、服务器、API、许可证、预算、外部团队和备用方案。
10. **时间与顺序：** 硬截止、里程碑、依赖顺序和范围—质量—时间取舍。
11. **验收与审批：** 环境、量化指标、评审指标、误差、例外和豁免批准人。
12. **治理：** 当前基线、变更批准人、版本规则、保密、合规和留存要求。

对无法从材料确定且会显著改变结果的事项建立 `Q-xxx`；不要为了形式完整询问低影响偏好。

## 3. 严格授权复核

| 操作 | 默认处理 | 必须记录 |
|---|---|---|
| 读取用户明确提供的材料 | 通常可执行 | 范围和失败项 |
| 创建指定需求文档 | 可在指定位置新建 | 路径和版本 |
| 覆盖或删除已有文件 | 需明确授权 | 精确目标和恢复方式 |
| 登录受限系统 | 任务需要且范围明确时只读访问 | 目的和页面 |
| 下载代码、依赖或镜像 | 需求分析阶段不执行 | 来源、许可、体积和环境 |
| 运行代码、服务、PoC或写库 | 需正式启动及相应授权 | 命令、环境、数据和回退 |
| 付费调用、发消息、提交或部署 | 需明确授权 | 费用、接收方、变更和回退 |
| 生产或不可逆操作 | 单独确认 | 对象、影响、审批和恢复 |

遇到敏感数据时，确认最小访问范围、存储位置、外传限制、脱敏方式和留存要求。

## 4. 完整追溯链

需要正式审计时使用：

```text
SRC/DEC → REQ → 交付物 → TASK → Prompt → 验收条件 → EVIDENCE
```

检查：

- 每个必须需求都有来源或用户决策。
- 每个必须需求进入某个交付物和任务。
- 每个任务出现在相应 Prompt 中。
- 每项验收结论都有证据。
- 取消或变更内容已同步到基线、任务、Prompt 和验收。
- 所有文件使用相同术语、版本、数字口径和目录名称。

## 5. 变更与验收复核

重大变更按以下顺序处理：

```text
提出 → 澄清 → 影响分析 → 批准/拒绝 → 更新关联文件 → 验证
```

影响分析至少覆盖目标、范围、交付物、任务、Prompt、资源、时间、技术路线、数据、安全、外部状态和验收。未获批准前，不把变更混入正式成果。

最终验收确认：

- 所有必须需求都有对应成果和证据。
- 交付物之间没有关键矛盾、缺项、失效链接或版本混用。
- 推断、限制、失败和未完成项均已披露。
- 可复现工作记录环境、版本、配置、命令、数据、结果和异常。
- 未执行超出授权范围的操作。
